# 排除优先设计说明

## 1. 决策目标

系统的任务不是证明患者“符合入组”，而是从中国癌症试验全集中剔除有明确证据的明显不相关或不能入组试验。没有充分排除证据的试验必须返回医学人员复核；相关性分数只排序，不设最低分、不默认 Top-K 截断。

## 2. 简化架构

```text
合作方 XML / 中文模板       WHO MCP 定期快照
             \               /
              解析、去重、保留原文
                       ↓
                本地 SQLite 试验库
                       ↓
 招募状态 → 明确癌种冲突 → 可计算硬条件 → 自由文本模型核查
                       ↓
      合作/非合作 × 潜在/已排除（逐条证据）
                       ↓
                  医学人员复核
```

不采用 A2A、消息总线、多 Agent 共识或多模型投票。当前只有一个边界清楚的批处理流程；这些组件不会增加召回或排除证据质量，只会增加状态、超时和审计复杂度。远程 MCP 只用于更新本地库，不是患者单次运行的依赖。

## 3. 数据模型与模板

数据库以 `trials` 为主体，子表包括 `trial_registry_ids`、`trial_sites`、`trial_contacts`、`trial_cohorts`、`trial_interventions`、`eligibility_criteria`、`trial_outcomes`、`trial_ethics_reviews` 和 `trial_support_sources`。`raw_json` 保存不可逆规范化前的完整来源对象。

中文模板保持“一个试验是一个完整档案”的使用方式，并提供两个入口：

- 第4版单试验表单：一个文件只对应一项试验，只有一个可见工作表，按提交信息、试验身份、疾病与干预、基础范围、注册号、队列、中心、入排标准、联系人、结局和伦理纵向填写。它是人工录入的推荐格式。
- 第3版批量模板：`试验主表` 一项试验一行，其余子表用“合作方试验编号”关联，适合合作方数据团队批量导出。

两种模板和 XML 最终进入同一数据库结构。第4版不要求合作方拆分“患者字段、比较符、值、单位”；结构化表达为可选项，系统只对可靠模式自动结构化，原文始终保留。

## 4. 中国试验证据

满足任一项即可进入中国试验池：

1. 主/辅助注册号以 `ChiCTR` 开头；
2. 来源链接为 ChiCTR 详情页；
3. 注册数据的国家字段明确包含 China/中国。

因此“中国试验”不能只等同于具有 ChiCTR 数据源的试验；在中国开展的 NCT 或其他注册库试验也应纳入。只有国家列表时保存为 `registry_country_list`，并明确标记“仅国家记录，非已核验中心”；只有具名中心记录才能作为中心证据。

## 5. 排除顺序

| 顺序 | 判断 | 自动排除条件 | 必须保留复核 |
|---|---|---|---|
| 1 | 数据范围 | 无任何中国证据、记录明确无效 | 国家或中心信息暂缺但已有 ChiCTR 证据 |
| 2 | 当前招募 | 暂停招募、停止招募、已完成 | 状态未知、不同中心状态不一致 |
| 3 | 疾病范围 | 患者与试验都能映射到明确癌种组且不相交 | 泛实体瘤、恶性肿瘤、未识别疾病、队列范围不清 |
| 4 | 硬性条件 | 年龄、性别、ECOG 等可计算字段明确冲突 | 患者字段缺失、单位/边界不明确 |
| 5 | 入选标准 | 强制入选条件有可靠结构化表达且患者明确不满足 | 仅自由文本、患者事实缺失 |
| 6 | 排除标准 | 强制排除条件有可靠结构化表达且患者明确触发 | 否定、例外、时序、实验室阈值或断句有歧义 |
| 7 | 模型自由文本 | 模型给出逐字试验证据、非空患者事实、明确排除类型并通过校验 | 任何不确定、信息未提及或证据未绑定情况 |

前置条件一旦明确排除即可停止该试验的后续判断。关键词命中、低相关性分数和“患者资料未提及”都不是排除证据。

## 6. 模型边界

`china-trial-exclusion-gater` Skill 只判断：明显疾病范围不相容、自由文本入选失败、自由文本排除触发。它不评估疗效、风险、论文、药物价值或治疗顺序。

- 每个排除必须逐字引用试验原文，并指向一个非空患者字段。
- 不跨队列拼接条件；WHO/MCP 条件可能因展示换行被拆段，片段不完整时保留。
- 模型不得输出“符合入组”，只能 `exclude` 或 `retain_for_review`。
- 排除置信度低于 0.80、证据类型不一致、ID 覆盖不完整或引文未绑定时，整个批次拒绝并重试。
- 只发送白名单临床字段，不发送姓名、电话、证件号、地址或原始病历全文。

## 7. 合作关系与更新

`partner_status` 只在最终结果中拆分合作/非合作，不改变医学判断。合作公司可以新增、暂停、终止；历史导入批次保留。注册号用于跨 XML、模板和 MCP 去重，来源更新时替换该试验子记录并保留最新原始对象。

## 8. 性能策略

- MCP 数据预先批量落地，本地患者运行不发远程 `get_trial` 请求。
- SQLite 一次加载试验全集和相关条件，避免逐试验查询。
- 确定性阶段先过滤，语言模型只处理剩余试验，并支持小批次并发和断点续跑。
- 默认不设置候选数量门槛；20 分钟目标按单患者完整线上运行计时，以模型响应和限流实测为准。
