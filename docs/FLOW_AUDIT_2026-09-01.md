# 项目流程审计与扩展患者测试（2026-09-01）

## 审计结论

当前项目主流程符合“排除优先、未知保留、医学复核”的目标，也没有引入 deep 分析或 A2A 运行时。大模型不是召回器，也不参与数据库导入、合作关系管理和确定性筛选；它只处理本地预筛后仍需理解的疾病范围与自由文本入排标准。

审计中发现并修复了四项问题：

1. 英文 `Female/Male` 与中文患者性别可能被确定性规则误判为冲突；现已统一成受控值。
2. 内部状态 `structured_eligible` 容易被误解为“符合入组”；已改成 `no_deterministic_exclusion`。
3. 模型批次缺失或失败时，合并流程原先会中止；现改为对应试验全部 `retain_for_review`，并记录降级批次，绝不因模型失败排除。
4. 模型曾把癌症治疗并发症/支持治疗试验仅凭 `cancer_type` 判为异癌种；Skill 已明确禁止该推断。相关旧结果已隔离，当前最终文件对受影响批次采用保守保留。

同时增强了 MiniMax 空响应处理、429 重试等待，并将默认并发从 16 调整为 8，以平衡速度和 Token Plan 限速。

## 实际运行流程与模型调用边界

| 阶段 | 主要工作 | 是否调用大模型 |
|---|---|---|
| 1. 数据导入 | ChiCTR XML、合作方工作簿、WHO MCP 快照映射到 SQLite，保留原始数据 | 否 |
| 2. 中国试验判定 | ChiCTR 注册号/链接，或国家字段包含中国 | 否 |
| 3. 本地确定性预筛 | 招募状态、明确异癌种、结构化年龄/性别/ECOG/入排谓词 | 否 |
| 4. 模型任务准备 | 仅把未被确定性排除的试验分成 `scope` 与 `eligibility` 批次；患者字段使用白名单且不发送 `patient_id` | 否 |
| 5. 模型排除预筛 | `run-model-jobs` 通过 `call_minimax` 调用 MiniMax-M2.7 | **是，唯一调用点** |
| 6. 输出校验 | 完整 ID 覆盖、原文证据绑定、患者字段存在、证据类型、置信度下限 | 否 |
| 7. 结果合并 | 仅将通过校验的明确排除移入排除区；失败/缺失批次保留复核；拆分合作/非合作 | 否 |

模型只允许形成三类判断：

- `scope_mismatch`：明确疾病范围不相交；
- `inclusion_failed`：明确患者事实直接违反强制入选标准；
- `exclusion_triggered`：明确患者事实直接触发排除标准。

未知事实、详情不足、时间窗歧义、泛实体瘤、多队列不清和支持治疗目标缺失均必须保留。项目中不存在疗效、风险、论文、机制或治疗价值分析。

## 测试结果

### 自动化回归

- 22 项单元/集成测试全部通过。
- 覆盖 XML 与两种工作簿往返导入、China 判定、NSCLC/SCLC 边界、缺失事实保留、双语性别、模型证据约束、模型失败降级与分桶守恒。

### 10 名合成患者的本地全量预筛

- 覆盖 NSCLC、SCLC、结直肠癌、乳腺癌、胃癌、胰腺癌、多发性骨髓瘤、儿童白血病、ECOG 3 和关键信息缺失。
- 每名患者遍历 101 条当前 Demo 试验，共 1,010 个患者—试验组合。
- 总耗时 1,463.617 ms，平均 146.362 ms/患者。
- 10/10 患者均通过：试验全集守恒、无重复 ID、汇总计数一致、合作/非合作分桶一致、潜在试验无排除理由。

### 3 名合成患者的真实 MiniMax 流程

- 患者：SCLC、HER2 阳性乳腺癌、关键信息缺失的 NSCLC。
- 确定性预筛后形成 56 个批次、110 个患者—试验模型任务。
- MiniMax 首轮通过 50/56；6 个批次因 429 或异常响应失败。低并发断点续跑后达到 56/56，两个有效波次总墙钟约 224.534 秒（3.74 分钟）。
- 输出校验实际拦截了 34 份不合格中间结果，主要问题为 ID 覆盖不完整、证据不是输入原文、患者字段不存在或证据类型不匹配；模型不得绕过校验直接排除。
- 人工审计发现支持治疗误排风险后，隔离了涉及 2 项试验的 6 个旧批次。因外部重跑审批两次超时，当前 v2 最终结果使用 50 个已校验模型批次（98 个任务），另外 6 个批次中的 12 个任务按保守原则保留复核。
- 当前最终计数：SCLC 13 潜在/88 排除；HER2 乳腺癌 13/88；信息缺失 NSCLC 23/78。三名患者的 101 条试验均守恒、无重复、分桶一致。

## 架构判断与剩余限制

- 当前顺序批处理架构足够，不需要 A2A、多 Agent 共识或消息总线。只有当多个合作方必须在各自网络内运行独立服务、平台不能持有全量数据并需要跨域实时查询时，才值得把 A2A 放到数据交换边界。
- 101 条试验只是当前 Demo 规模，不能直接代表约 900 或 2,000 条数据库的最终性能。真实模型阶段的成本与确定性预筛后剩余候选数、标准长度和 API 限速共同相关。
- 20 分钟目标在本次 3 人/110 任务测试中有充足余量，但扩大数据库后仍需用完整目标库做一次批量压测；应继续保留断点、低并发重试和失败保留策略。
- 模型输出具有波动性。证据绑定校验与人工抽查不是冗余门禁，而是防止误排除所需的最小安全边界。
